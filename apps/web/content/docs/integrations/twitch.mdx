```bash
npm i jev-events @jev-events/twitch
```

`twitch.chat(channel)` works in two modes:

| | Anonymous | Signed in |
| --- | --- | --- |
| Setup | None | A bot account that moderates your channel |
| Reads chat through | Twitch's public chat server | EventSub, Twitch's official event API |
| Channels | Any public channel | Any channel |
| Native actions | Dry-run only | Where the bot is a moderator |

Start anonymous to try questions on a busy channel, then sign in when you're ready to act.

## Sign in a bot

<Steps>
<Step>

**Create a Twitch application.** At the [Twitch developer console](https://dev.twitch.tv/console/apps), register an app with client type **Public** and any redirect URL, such as `http://localhost`. You only need its client ID. Public apps have no secret, and sign-in uses Twitch's device code flow.

</Step>
<Step>

**Sign in as the bot.** Use a separate Twitch account for the bot, so its actions are clearly labeled in your mod log.

```bash
npx jev-events auth twitch --client-id <client id>
```

Open the link it prints and enter the code while signed in as the bot. The tokens are saved to `.jev-events/credentials.json`, which only your user can read. Its folder gets a `.gitignore`, and refreshed tokens are written back automatically.

</Step>
<Step>

**Make the bot a moderator.** In your channel's chat, type `/mod <bot name>`.

</Step>
<Step>

**Pass the sign-in to the source.**

```ts
twitch.chat("mychannel", { auth: twitch.auth.fromFile() });
```

</Step>
</Steps>

On a server, use `twitch.auth.fromEnv()`, which reads `TWITCH_CLIENT_ID`, `TWITCH_ACCESS_TOKEN` and optionally `TWITCH_REFRESH_TOKEN` and `TWITCH_CLIENT_SECRET`. If you store tokens yourself, `twitch.auth.withTokens(tokens, onRefresh)` hands you rotated tokens to save.

`jev-events auth twitch` asks for these scopes. Pass `--scopes` to ask for fewer.

| Scope | Needed for |
| --- | --- |
| `user:read:chat` | Reading chat through EventSub |
| `user:write:chat` | `reply`, `say` |
| `moderator:manage:banned_users` | `timeout`, `ban` |
| `moderator:manage:chat_messages` | `deleteMessage` |
| `moderator:manage:warnings` | `warn` |
| `clips:edit` | `clip` |

## Actions

| Action | What it does |
| --- | --- |
| `twitch.timeout({ seconds?, reason? })` | Times the chatter out. 600 seconds by default. |
| `twitch.ban({ reason? })` | Bans the chatter. Prefer a timeout unless you're sure. |
| `twitch.deleteMessage()` | Deletes the message. |
| `twitch.warn({ reason? })` | Sends a warning the chatter must acknowledge before chatting again. |
| `twitch.reply(text)` | Replies to the message in chat, as the bot. |
| `twitch.say(text)` | Says something in chat, as the bot. |
| `twitch.clip()` | Clips the live stream. Pair it with `burst()` so a hype moment makes one clip, not fifty. |

`reason` and `text` can be strings or functions of the event. The default reason shows moderators why the bot acted, for example `jev-events: kind:hateful (93%)`.

```ts
chat.on(
  "kind:question",
  { min: 0.8 },
  twitch.reply((e) => `Noted for the Q&A, ${e.item.author.name}!`),
);
```

## Chat items

Handlers receive a `TwitchChatItem`:

| Field | Type | Notes |
| --- | --- | --- |
| `text` | `string` | The message, with emotes as their names |
| `author` | `{ id, login, name, roles }` | `roles` holds `broadcaster`, `moderator`, `vip`, `subscriber` or `staff` |
| `channel` | `string` | The channel's login |
| `firstMessage` | `boolean` | The chatter's first message in this channel |
| `reply` | `{ author, text }` | The message this one replies to, if any |
| `bits` | `number` | Bits cheered with the message |

Jev sees the text, the author's name and roles, `firstMessage` and the reply, plus the three messages before it. See [what Jev sees](/docs/concepts/context).

## Good to know

- **Protected users.** Actions never run on the broadcaster, moderators, VIPs or Twitch staff.
- **Ignored messages.** `!commands` and well-known bots such as Nightbot and StreamElements are skipped before judging, so they cost nothing. Pass `ignore: { commands: false }` to judge commands too, or give `bots` your own list of logins to replace the built-in one.
- **Fresh or not at all.** Messages that waited more than 10 seconds for a request slot are dropped instead of acted on late.
- **Reconnects.** Both modes reconnect with backoff. Items that arrive during a reconnect are not replayed.
